## 1. 这是什么

「任务面板」是运行在 DeepSeek Harness Web 界面上的一个悬浮插件。它把当前会话里 AI 正在推进的各项工作**汇总成一块悬浮小窗**，让您在一边看 AI 干活的同时，随时一眼掌握：

- **短期任务**：您每次**让会话「去做某件事」**都算一条（例如「请将插件提交到 GitHub」→一条；「把插件移入新目录并撰写文档」→两条）。**执行过程中的具体操作**（装工具、跑命令、验证、清理、汇报等）不算任务；
- **长期任务**：当前会话中**明确委派或共同商定的长期任务**——即会话建立的目标（goal）：进行到第几轮、有没有卡住。AI 的内部执行机制（子代理、后台任务、工作流）**不展示**，它们与工具调用一样属于「干活的手段」而非「任务的本身」。

面板**只读**：只展示，不提供任何操作按钮，绝不干预 AI 的工作。数据全部来自 Harness 自身（待办、目标、子代理均为会话内部状态），**无需手动登记任务**。

它适合以下场景：

| 场景 | 价值 |
|---|---|
| AI 执行多步骤任务时 | 不需要翻对话记录，悬浮窗直接看进度 |
| 长期任务跨多轮运行（goal） | 看到已进行轮数、当前阶段、受阻原因 |
| 并行委派多个子代理 | 一眼看出哪些还在运行、哪些已结束、跑了多久 |
| 只想盯一眼 | 折叠成右下角鲸鱼按钮，不打扰、无数字角标 |

## 2. 功能一览

| # | 功能 | 说明 |
|---|---|---|
| 1 | 右下角悬浮窗 | 所有页面常驻（对话页、设置页等），不遮挡主要操作区 |
| 2 | 可拖动 | 按住标题栏拖动到任意位置，位置会被记住（浏览器本地存储） |
| 3 | 可折叠 | 点击「—」折叠为**鲸鱼 🐳 按钮**；有任务运行时鲸鱼右上角有闪烁小点 |
| 4 | 两组任务 | 「短期任务」= **您让会话去做的每一件事**（一句话一件事，执行过程不算）；「长期任务」= **目标（goal）**。子代理、后台任务、工作流等 AI 内部执行机制不展示 |
| 5 | 状态一目了然 | 每项任务有状态标签：进行中 / 等待 / 已完成 / 已暂停 / 受阻 / 已结束 |
| 6 | 进度展示 | 短期组有总体进度条（x/y 已完成）；目标有**轮数进度条**（X/Y 轮，无上限时显示已进行轮数） |
| 7 | 时间信息 | 每项显示开始时间与已用时长（待办从「变为进行中」起算） |
| 8 | 已完成保留 | 已完成/已结束任务置灰保留，可一键折叠为「已完成 N 项」 |
| 9 | 排序规则 | 组内：进行中 > 等待 > 已完成；同状态下新任务在前 |
| 10 | 自动刷新 | 每 **1 分钟**自动拉取一次；页头 **↻** 按钮可**立即手动刷新** |
| 11 | 更新时间 | 面板底部显示「更新于 今天 HH:MM」确认数据新鲜度 |
| 12 | 仅当前会话 | 面板只显示当前打开会话的任务，切换会话自动跟随 |
| 13 | 明暗主题 | 使用界面设计令牌（CSS 变量），亮色/暗色主题自动适配 |
| 14 | 零性能负担 | 轮询仅每次一个极小的 JSON 请求；无侵入、无监听副作用 |
| 15 | 不自动弹出 | 折叠后保持折叠，新任务出现也不自动展开（不打扰原则） |
| 16 | 跨轮保留 | 任务清单不会因新一轮对话而清空，持续显示直到 Agent 提交新清单 |
| 17 | 疑似长期提示 | 会话没有目标但识别到长期需求时，显示「疑似长期需求」提示框，不再静默空白 |

## 3. 界面说明

### 3.1 面板展开态

```
┌────────────────────────────────────────────┐
│ ● 任务面板          每 1 分钟刷新   ↻   —  │ ← 标题栏（可拖动）
├────────────────────────────────────────────┤
│ 短期任务          3 / 5 已完成  展开已完成  │
│ ▓▓▓▓▓▓░░░  (组进度条)                     │
│ ● 编写文档            进行中  今天 14:32 · 3分20秒 │
│ ● 测试插件            等待    今天 14:30 · 2分10秒 │
│ ⚪ 发布版本            已完成  开始 14:32 · 已用 5分钟 │
│ 长期任务          目标                     │
│ ┌─ 目标 ───────────────────────── 进行中 ┐ │
│ │ 完成任务面板插件开发与文档              │ │
│ │ ▓▓▓▓▓░░░░░  已进行 2 / 5 轮            │ │
│ │ 开始 今天 13:05 · 已用 1小时12分        │ │
│ └─────────────────────────────────────────┘ │
├────────────────────────────────────────────┤
│ 仅当前会话 · 更新于 今天 15:01             │
└────────────────────────────────────────────┘
```

（上图为结构示意，实际样式随主题生效。子代理、后台任务等 AI 内部执行机制不在此面板展示。）

### 3.2 折叠态

- 右下角：**46px 圆形按钮 + 🐳 鲸鱼图标**；
- 有任务运行中 → 鲸鱼右上角出现**闪烁蓝点**（无任何数字角标）；
- 点击展开面板。

### 3.3 字段含义

| 字段 | 含义 |
|---|---|
| 状态标签 | 短期：等待 / 进行中 / 已完成；长期目标：进行中 / 已暂停 / 受阻 / 已完成 |
| 进度条（短期组） | 已完成项数 / 总项数 |
| 进度条（目标） | roundsStarted / maxGoalRounds；目标未设轮数上限时只显示「已进行 N 轮」 |
| 受阻原因 | 目标被标记 blocked 时，红字显示具体原因 |
| 开始时间 | 待办：首次变为「进行中」的时刻；目标：创建时刻 |
| 已用时长 | 进行中 = 到现在；已完成 = 完成时刻 − 开始时刻 |
| 更新于 | 最近一次成功获取数据的时刻 |

## 4. 数据来源与更新机制

### 4.1 数据流

```
浏览器面板 (lib/client.js)
   │  每 60 秒轮询 + 手动 ↻
   ▼
GET /plugins/dsh-task-panel/state?session=<当前会话ID>
   │  宿主端 (lib/index.js) 收集
   ▼
JSON 响应
   total: 短期任务 = 首选 Agent 的 todo 清单（用户级粒度）
                     兜底 = 当前轮用户消息（Agent 未写清单时自动推导「您要做的事」）
          长期任务 = 当前会话目标（goals 服务，用户级粒度）
   （子代理、后台任务、工作流为 AI 内部执行机制，不返回、不展示）
```

### 4.2 响应示例

```json
{
  "session": "session-350ccf9f-...",
  "goal": {
    "id": "goal-1",
    "revision": 3,
    "objective": "完成插件开发",
    "phase": "active",
    "roundsStarted": 2,
    "maxGoalRounds": 5,
    "blockedReason": null,
    "createdAt": 1738200000000,
    "updatedAt": 1738200600000
  },
  "todos": [
    { "content": "编写文档", "status": "in_progress", "startedAt": 1738200300000, "endedAt": null },
    { "content": "测试插件", "status": "pending", "startedAt": null, "endedAt": null },
    { "content": "发布版本", "status": "completed", "startedAt": 1738200000000, "endedAt": 1738200500000 }
  ]
}
```

（响应不含子代理/后台任务/工作流数据——它们属于 AI 内部执行机制。）

### 4.3 关键规则

- **短期任务**：优先取会话日志中**最后一次** `todo/write` 事件（每次模型写 todo 都是整表替换）；**清单跨轮保留**——新的一轮开始时不会清空，面板持续显示上一轮的任务，直到 Agent 提交新清单（与 Harness 内置 todos 投影的「每轮清空」不同，这是面板为「持续可见」刻意采用的语义）。
- **兜底自动识别**：若 Agent 从未写过任何 todo 清单（内置工具说明允许琐碎工作跳过），宿主端会从**会话的全部用户消息**（跨轮积累、去重）自动推导「您要做的事」：剔除问题、确认语（「好了」「可以」「谢谢」）与闲聊后，每条用户请求显示为一条短期任务（最新一条标记进行中）。因此面板**不依赖 Agent 配合**也能主动展示短期任务；Agent 一旦写过清单（即使之后清空），清单即成为权威数据。
- **短期任务粒度约定**：插件通过系统提示词（`task-panel:task-convention`，应用顺序 116）向每个会话的代理声明：**用户每次让会话「去做某件事」都对应一条短期任务**（一句话含多件事则拆多条；与用户共同商定要做的事同样计入；用户的问题/咨询/确认语如「好了、可以、谢谢」不记录）；**具体执行过程里的操作不算任务**——安装工具、生成密钥、运行命令、语法检查、验证预检、清理旧副本、写测试、汇总汇报等都不写入清单，需要说明时在回复中简要交代即可。因此面板的短期任务即「用户要做的事」清单。
- **开始/完成时间**：由会话日志推导——待办项首次出现 `in_progress` 记为开始，首次 `completed` 记为完成。这是**派生数据**：同一项被模型改回「等待」不会重置已记录的时间。
- **长期任务**：读取 `goals` 服务的当前视图（需对应会话的 agent 处于存活状态）；若不可用则该项显示为空，不影响其他数据。同一约定要求目标只对应「用户明确要求或共同商定的长期完成目标」，代理不为内部子目标/分段创建目标。
- **疑似长期需求提示**：当会话**没有任何目标**时，若用户消息中识别到长期意图（如「长期维护」「持续跟踪」「一直做」「定期」等），面板会在长期任务区显示虚线提示框「疑似长期需求（尚未建立目标）」并列出候选，引导建立目标——避免「长期任务区静默空白」。
- **不展示内部机制**：子代理、后台任务、工作流是代理的执行手段（与工具调用同类），按新定义**不进入长期任务**，宿主路由也不读取它们。
- **错误降级**：任何一项读取失败，面板静默返回该项的空数据或保留上次快照，绝不导致页面报错。

## 5. 安装 / 启用 / 卸载

### 5.1 快速启用

1. 将本仓库安装到您的 dsh profile（见下节 5.2）；
2. **重启** dsh web（关闭运行 dsh 的窗口后重新运行启动脚本，如 `start-dsh.cmd`）；
3. 打开 Web 界面（默认 http://127.0.0.1:3080）→ 进入任一会话 → 右下角出现任务面板。

源码即插件本体：修改本仓库文件后重启即生效（`link:` 安装为目录链接，无需重新安装）。

### 5.2 通用安装方法（其他机器 / 其他 profile）

```sh
# Linux / macOS（Git Bash），或 Windows 的 PowerShell（注意路径不含中文，避免编码问题）
dsh plugin --profile web add link:/path/to/deepseekHarnessPlugin
# 或安装为 npm 包 / git 仓库
dsh plugin --profile web add <npm 包名或 git URL>
```

- Windows 下用 `link:` 或 `file:` 本地路径安装时，**路径请避免中文和空格**（否则 pnpm 会把路径写坏，表现为依赖字符串乱码）。
- 安装后**重启** `dsh web` 生效。
- 图形化替代：设置 → 插件 →「插件管理器」标签页，也可安装来自 npm / Git 的插件（本地路径请优先用命令行）。

### 5.3 卸载

```sh
dsh plugin --profile web remove @dsh-local/task-panel
```

重启后面板消失。或通过设置 → 插件 → 插件管理器卸载。

### 5.4 升级（修改插件后）

修改本仓库下的代码 → 重启 Web 服务即加载新版本。无需重新执行安装命令（`link:` 安装是目录链接，源码改动直接生效）。若修改了 `package.json` 的 name/bundles 元数据，则重新执行一次 install。

## 7. 架构总览

```
┌─────────────────────── 浏览器（Client）───────────────────────┐
│  dsh web 应用的客户端模块系统（__ModuleLoader__）              │
│    └─ lib/client.js：任务面板 React 组件                      │
│         · createRoot 门户挂到 document.body（覆盖所有页面）   │
│         · 每 60 秒 fetch 宿主路由；↻ 手动刷新                │
│         · 拖动 / 折叠 / 已完成折叠 / localStorage 记住偏好   │
└───────────────────────────┬──────────────────────────────────┘
                            │ GET /plugins/dsh-task-panel/state?session=…
┌───────────────────────────▼────────────── 宿主端（Host）──────┐
│  lib/index.js                                                  │
│    ├─ webServer.register(路由)                                  │
│    ├─ 读取 sessions 服务 → 当前会话对象                         │
│    ├─ 折叠会话日志 → todos（todo/write + turn/start 语义）     │
│    ├─ 读取 goals 服务 → 当前目标视图（agent 存活时）           │
│    ├─ systemPrompt 注册任务粒度约定（task-panel:task-convention）│
│    └─ 所有依赖均为可选读取（ctx.get），缺失/异常静默降级        │
└────────────────────────────────────────────────────────────────┘
```

插件由两部分组成，通过一条 JSON 路由通信：

- **Host（lib/index.js）**：在宿主进程注册只读 HTTP 路由，从 Harness 的会话日志与两个服务（sessions / goals）收集当前会话的用户可见任务，返回纯 JSON；另向 `systemPrompt` 注册任务粒度约定。**零注入、零写操作**。
- **Client（lib/client.js）**：浏览器端 React 组件，通过客户端模块协议（`dsh.client` 元数据 + `window.__ModuleLoader__`）随 Web 应用启动自动挂载，仅使用 `sessions` 一个客户端服务拿到「当前会话 ID」。

完整技术细节（数据契约、折叠算法、模块加载协议、主题令牌、扩展点）见 **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**。

## 8. 常见问题（FAQ）

**Q1：重启后没有看到面板？**
- 确认重启的不是浏览器标签页，而是 `dsh web` 进程本身（关闭黑色窗口后重新运行 start-dsh.cmd）。
- 检查 设置 → 插件 → 插件管理器：应看到「任务面板」已启用；若显示启动失败，把错误信息截图发回，或在插件管理器点「Ask the agent to fix」。

**Q2：面板会消耗很多资源吗？**
不会。面板仅每 60 秒发一个约 1 KB 的请求，无 WebSocket、无监听器、无后台任务。

**Q3：为什么短期任务有时是空的？**
两种正常情况：① Harness 规定，每轮对话开始（turn/start）时待办清单即清零，模型在开始干活后重新提交（与内置行为一致）；② 该轮对话中没有「让会话去做的事」（比如只是提问、聊天、确认，不算任务）。**注意**：即使 Agent 没有写 todo 清单，面板也会自动从您本轮的消息推导任务（见 Q14），所以「清单没写」不会导致空白。

**Q4：短期任务项的粒度是怎么保证的？**
插件在系统提示词中向会话声明了约定（`task-panel:task-convention`）：**您每次让会话「去做某件事」= 一条短期任务**，执行过程里的操作不算任务。示例：您说「请将这个插件提交到 GitHub」→ 一条「发布插件到 GitHub」；您说「把插件移入 D:\... 并撰写文档」→ 两条「移动插件文件位置」「撰写介绍文档」——而不是 AI 的安装、生成密钥、验证、推送等步骤逐条展开。若 Agent 未登记清单，面板先以您消息原文临时展示，概念一致。

**Q5：短期任务项的时间是怎么来的？**
由会话日志推导：该项首次出现「进行中」记为开始时间，首次「已完成」记为完成时间。若模型中途改回等待，时间不会被重置。

**Q6：目标没有轮数上限时进度怎么显示？**
显示「已进行 N 轮」文本，不显示百分比进度条；有上限时显示 X/Y 轮进度条。

**Q7：面板显示的范围是什么？**
严格「仅当前会话」。切换到别的会话时，面板自动跟随切换；已关闭/未打开的会话不显示。

**Q8：为什么面板里看不到子代理/后台任务/工作流？**
按新的任务定义，子代理、后台任务、工作流属于 AI 的**内部执行机制**（像工具调用一样是「干活的手段」），不是用户可见的任务，因此在长期任务中不展示；宿主路由也不读取这些数据。如果您希望某个特定委托被面板追踪，请把它明确为任务（例如「用 AgentTeams 完成 X」这类需求本身就是一条任务）。

**Q9：为什么不用服务器推送/事件流，而用轮询？**
轮询实现最简单、与宿主解耦（零服务依赖、零挂载顺序问题），每分钟一次的频率对体验无影响，且失败时天然退化为「保留上次快照」。

**Q10：面板和"宠物"（pet）图标会重叠吗？**
当宠物功能(右下角宠物)启用时可能与本插件的鲸鱼按钮重叠。当前宠物为隐藏状态。如需要，可把鲸鱼按钮向右上移（改 `lib/client.js` 中 Dot 组件的 right/bottom 值）或移开宠物位置。需要的话我可以直接调整。

**Q11：安全吗？**
插件是只读的：宿主端不调用任何写接口、不修改会话、不关闭/停止任务；路由仅回环地址可访问（与 Web 界面同源），响应只包含任务元数据。

**Q12：我想改成英文界面 / 调整刷新间隔？**
搜索 `lib/client.js` 中的 `POLL_MS`（刷新毫秒数，默认 60000）与所有中文文案字符串，改完重启即可。

**Q13：卸载后想再装回来？**
见 [5.2 通用安装方法](#52-通用安装方法其他机器--其他-profile)。

**Q14：在其他会话里，面板怎么「主动」认出短期任务？**
双通道保证：① Agent 在系统提示词约定下必须登记每个用户任务到 todo 清单，且**清单跨轮保留**（不会因新一轮而清空）；② **兜底识别**——若 Agent 从未写清单，宿主端从会话全部用户消息自动推导任务（剔除提问/确认语/闲聊，最新一条标为进行中）。所以即使 Agent 完全没配合，面板也会显示您说过的「要做的事」。

**Q15：长期任务怎么才能出现？**
两种途径：① Agent 按约定对您明确的长期目标建立目标（goal）后，长期任务区显示目标卡（轮次进度/阶段/原因）；② 若会话没有任何目标，但您的消息里含长期意图（长期/持续/维护/跟踪/定期等），面板会显示「疑似长期需求」提示框并列出候选——此时可让会话为其中一条建立目标。

## 9. 开发者指南

**环境要求**：Node.js ≥ 22；无需任何构建步骤（纯 JavaScript ESM + React.createElement，无 TypeScript/打包器）。

```sh
# 1) 语法检查
node --check lib/index.js
node --check lib/client.js

# 2) 宿主端逻辑冒烟测试（模拟会话日志 → 验证路由 JSON 契约）
node smoke.mjs

# 3) 修改后生效：重启 dsh web（link: 安装直接读取本目录）
```

**开发约定**：

- `lib/client.js` 是**浏览器模块**，必须以 `window.__ModuleLoader__.load({ id, factory })` 协议注册导出 `{ inject, apply }`；不可使用 import/JSX/TS（与官方动态客户端的限制同理——本插件为免构建直接手写）。
- `lib/index.js` 是 ESM 插件（`export function apply`），所有依赖用 `ctx.get()` 可选读取并处理缺失；不声明 `inject` 硬依赖。
- 客户端 React 使用 `React.createElement`，禁止 JSX（无构建）。
- 主题颜色一律使用 `--dsw-*` CSS 变量并带硬回退值，保证亮/暗主题。
- 改动后请在**新会话**里让 AI 复查（本插件的面板会显示该会话自己的任务，方便自查）。

**测试覆盖现状**（`smoke.mjs`）：
- 任务粒度约定注册断言（`task-panel:task-convention` 名称与内容）；
- todo 折叠与时间推导（in_progress/completed 的首见时间）；
- 目标视图映射（轮数、上限、受阻原因、时间戳）；
- 宿主路由**不暴露**子代理数据（内部执行机制）；
- 空会话参数与未知会话的优雅降级。
